# Skill: Off-Hours Research Routine

Runs daily 20:00 ET via the `stonks-off-hours` cron. Market closed — no trading, don't call `scripts/executor.py`. Read current tickers first via `python3 scripts/trader_query.py positions` + `watchlist`, pass them explicitly to the scripts below (no stale defaults).

| Step | Command | Output |
|---|---|---|
| 1. Position reconciliation | `python3 scripts/reconcile_positions.py` | (2026-08-03) Cross-checks live Alpaca positions against `trader_db`'s `positions` table — catches phantom positions (STVN 2sh vs 3sh, KEX/DXCM patterns, `tasks/pending.md`) before they compound. Writes `state/reconciliation_status.json`; a critical finding (phantom Alpaca position) blocks trading via `workspace_review.py --gate` on the next tick until resolved. Run first, before anything else touches positions. |
| 2. News + sentiment | `python3 scripts/news_collector.py <tickers>` | Fresh RSS → local `news_cache` table (`state/trader.db`, additive). Sentiment over last 24h. Note real catalysts, not noise. |
| 3. Exercise wired signals | `get_macro` (once), `get_fundamentals`/`get_flow`/`get_insiders`/`get_risk`/`get_technical_scan` (per ticker) | Zero-risk since the market's closed — this is where those tools actually get practiced. Log real-vs-errored per tool; `get_risk`/`get_technical_scan` are expected to report unavailable — paywalled on LoneStarOracle's free tier, not down (`skills/data-bus-fallback.md`). See `skills/self-improving-agent.md`. |
| 4. Signal scorecard | `python3 scripts/signal_scorecard.py` | Real empirical hit rate per signal from `state/trader.db`'s `training_examples` table. Signals under 10 labeled examples show `insufficient_data`, not a fake precise number — that's expected while volume is low, not a bug. |
| 5. Decision-tree scorecard | `python3 scripts/tree_scorecard.py` | Sibling to step 4, same `insufficient_data` contract, but scores `decision_heuristics.md` node hit rates (see that script's own docstring for the tagging convention, `tick_prompt.md` step 8). Writes `state/tree_scorecard.json`. This is what grounds a node's tier — was never being run until 2026-08-11. |
| 6. Replay check | `python3 scripts/replay_check.py <tickers>` | 200d backtest, v1.0 vs v1.1 vs v1.2 side by side — empirical check on whether hardened rules actually help. Caveat: RSI-band entry proxy, not full qualitative judgment; v1.2's sector veto/VIX-tiering/quality-gate aren't modeled (no sector/VIX/fundamentals data here). |
| 7. Brief log | Write 5-10 lines to `off_hours/YYYY-MM-DD.md` | Notable news, which signals worked vs errored, scorecard status changes, and replay numbers + whether they still support the current strategy version. Do NOT edit `strategy.md`/`params.json` here — that's the nightly job's call, with fuller context. |
