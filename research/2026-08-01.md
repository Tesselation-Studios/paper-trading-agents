# Research — 2026-08-01

## Hypothesis

The gentler scale-in cap (v1.7-gentle, scale_in_max_multiple=1.5) produces
better both-half Sharpe than the full v1.7 cap (3.0x), even on aggregate
where v1.7 shows higher raw return.

**Observation**: Jul 31 RDDT loss (-22.66% in 18 min) showed the danger of
momentum-chasing at full size. The overnight research (12 runs, 600+
variants) already flagged that scale_in_max_multiple=1.5 strictly dominates
3.0 on every aggregate metric. But nobody had run the split-window test.

## Test

`python3 scripts/replay_check.py --split-window` on live universe (34
tickers, 104 trading days). Key comparison: v1.7 (3.0x cap) vs v1.7-gentle
(1.5x cap). Both pass the promotion bar (Sharpe > 0 both halves).

## Results

### Aggregate (full window)

| Metric | v1.7 (3.0x) | v1.7-gentle (1.5x) | Delta |
|--------|-------------|--------------------|-------|
| Sharpe | 1.918 | 2.407 | **+0.489** |
| Return | +18.2% | +12.7% | -5.5% |
| Win Rate | 0.512 | 0.512 | 0 |
| Max DD | -8.45% | -5.11% | **+3.34%** |
| Trades | 84 | 86 | +2 |

### Split-window

| Half | Metric | v1.7 | v1.7-gentle |
|------|--------|------|-------------|
| 1st | Sharpe | 1.374 | 1.261 |
| 1st | Return | +7.53% | +2.72% |
| 1st | Win Rate | 0.326 | 0.349 |
| 1st | Max DD | -8.45% | -5.11% |
| 2nd | Sharpe | 3.583 | **4.183** |
| 2nd | Return | +10.71% | **+11.63%** |
| 2nd | Win Rate | 0.667 | **0.675** |
| 2nd | Max DD | -3.84% | **-2.54%** |

## Analysis

**v1.7-gentle is strictly better in the second half on every metric** and
trades off lower first-half return for dramatically less drawdown (-5.11%
vs -8.45%). The full v1.7 (3.0x) only wins on first-half raw return
(+7.53% vs +2.72%) — achieved through greater concentration risk that
produced 3x the max drawdown.

The second-half dominance is the key story: v1.7-gentle not only catches
up to v1.7's second-half return, it exceeds it (+11.63% vs +10.71%) while
using gentler scaling. This suggests the 3.0x cap was consistently
over-concentrating in winners that then reversed — the classic "scale in
too aggressively" failure mode.

**In the context of the RDDT loss**: A 1.5x scale-in cap wouldn't have
prevented the RDDT entry (that was a fresh entry, not a scale-in), but it
reduces the systemic risk of over-concentration when an entry works out
and the strategy doubles down at 3x the base size. The RDDT pattern
(peak-entry cascade) is distinct from the scale-in pattern, but both are
symptoms of the same root cause: our sizing mechanism amplifies winners
too aggressively without adequate protection when they reverse.

## Honest Assessment

- **Strength**: Split-window validated. Both halves positive Sharpe. The
  pattern is consistent across both periods.
- **Weakness**: The 1.5x cap sacrifices meaningful first-half return
  (+2.72% vs +7.53%). In a bull market, the 3.0x cap captures more upside
  when the momentum continues. The 1.5x cap is a structural choice to
  trade upside for downside protection.
- **Caveat**: This is a rule-based proxy (RSI 45-65 entry, +3% pnl
  triggers scale-in). The live LLM strategy uses judgment, not a hard
  multiple — so the proxy doesn't perfectly model real decisions.

## Verdict

**Confirmed — but with nuance.** The 1.5x cap produces better risk-adjusted
returns (Sharpe +0.49, max DD -3.34% less) and dominates the second half.
The 3.0x cap only wins on first-half raw return at 3x the drawdown. The
evidence supports moving the proxy's constant from 3.0 to 1.5 — this
improves the proxy's accuracy as a model of the kind of cautious sizing
the live strategy should use. Not a live strategy change (the real
strategy uses LLM judgment), but a proxy improvement that makes future
backtests more realistic.
