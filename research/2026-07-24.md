# Research — 2026-07-24: MACDh-flip exit & CHOPPY-gating robustness

## Hypothesis

The off-hours brief (Jul 24 00:28) claimed v1.1 (MACDh-flip exit + CHOPPY-gated entries) was "dominating" v1.0 with Sharpe 0.991 vs 0.464 — but that was on only 6 live tickers. **Hypothesis: this was cherry-pick noise. On a broad random universe, v1.1's extra rules do not systematically improve risk-adjusted returns vs v1.0's simpler fixed stop/target-only exit.**

## Test

Two independent tests, both parameterized (no files edited):

### Test 1: Broad-universe head-to-head (182 tickers)
Ran both v1.0 and v1.1 as isolated single-ticker backtests on 250 random NYSE/NASDAQ tickers ($1-$500 band), seed `2026-07-24-research-choppy-gate`. 182 tickers had ≥3 trades in at least one variant.

### Test 2: Live-universe split-window (8 tickers)
`python3 scripts/replay_check.py --split-window` on all 8 live positions+watchlist tickers (BFST, BKSY, BOX, F, FHB, IP, RCAT, VTEX). All 7 registered variants compared.

## Results

### Broad universe (182 tickers, head-to-head)
| Metric | v1.0 (no gate, no MACDh-flip) | v1.1 (CHOPPY-gate + MACDh-flip) |
|--------|------|------|
| Mean Sharpe | -0.203 | +0.023 |
| Median Sharpe | -0.051 | +0.052 |
| % Sharpe positive | 49.5% | 52.9% |
| Mean return | +0.412% | +0.181% |
| Head-to-head wins | **109** | 72 |
| Ties | 1 | — |
| Tickers where gating blocked entries | — | 66 |

v1.0 wins head-to-head on **60% of tickers** (109/182). v1.1's slightly higher aggregate Sharpe (mean +0.023 vs -0.203) is driven by outlier tickers where gating helped a lot (e.g. CROX: Sharpe jumped 2.519→3.505), not systematic improvement.

### Live universe split-window (8 tickers interleaved)
| Variant | 1st Half Sharpe | 2nd Half Sharpe | Robust? |
|---------|----------------|-----------------|---------|
| **v1.0** | **2.302** | **1.024** | ✅ **ONLY ONE** |
| v1.1 | 1.544 | 3.463 | ❌ inconsistent |
| v1.2 | -1.474 | 0.313 | ❌ |
| v1.7 | 0.510 | 1.781 | ❌ inconsistent |
| v1.7-gentle | 0.583 | 1.932 | ❌ inconsistent |

**v1.0 is the ONLY variant with positive Sharpe in BOTH halves.** Every variant that adds MACDh-flip exit (v1.1, v1.7, v1.7-gentle) is inconsistent between halves — good in one, mediocre in the other. The aggregate numbers hide this.

## Verdict

**Clear negative on MACDh-flip + CHOPPY-gating as mechanical rules.** Neither improves robustness vs the simpler v1.0 baseline. The off-hours brief's v1.1 "dominance" was small-sample noise (6 tickers) that failed to replicate on 182.

### Why this doesn't change the live strategy (yet)
1. The harness can't model the **near-zero oscillation guard** (strategy.md's "MACDh crosses near zero ±0.003 range" — verified 3+ times live: DVN, WSC, F on Jul 23). This guard PREVENTS bad MACDh exits. Mechanically applied MACDh-flip (what the harness tests) is a noisier signal than what we actually use live.
2. The harness can't model **qualitative exit judgment** — the live trader weighs MACDh alongside price confirmation, thesis integrity, and volume context. The harness just flips on sign change.
3. v1.0's simplicity advantage may partially stem from doing LESS — fewer rules = fewer opportunities for a rule to misfire. But live trading needs exit discipline beyond just stop/target; the question is whether MACDh is the right signal.

### What this DOES change
- **Downgrades confidence in MACDh-flip as a standalone mechanical rule.** The live near-zero guard is doing heavy lifting.
- **Validates the v1.5 direction**: CHOPPY-gating (blocking entries entirely during high vol) is not systematically beneficial. "Regime sizes, doesn't block" was correct.
- **Monitoring**: MACDh-flip exit win rate should be tracked separately from trailing-stop exits in the journal. If MACDh-flip exits underperform the near-zero-guard-adjusted baseline, the rule deserves a formal review.

**Status**: Logged. Does not clear promotion bar (finding is about what DOESN'T work, not a proven improvement). No strategy.md/params.json changes.

# Follow-up — 18:10 ET: v1.0 + scale-into-winners

## Observation
Previous test: v1.7/v1.7-gentle (v1.1 core + scale-into-winners) failed split-window robustness. v1.0 was the ONLY robust variant. **Question: was it the scale-into-winners logic that broke things, or the v1.1 core (MACDh-flip + regime gate) that it was built on?**

Also, live journal data: trailing stop win rate 4W/8L (33%). The harness uses fixed stop/target only (never models trailing stops), so v1.0's robustness might partially reflect "no premature trail-stop exits."

## Hypothesis
Building scale-into-winners on v1.0's proven-robust core (simple RSI 45-65 entry, fixed stop/target, NO MACDh-flip, NO regime gate) would produce a robust split-window strategy — unlike v1.7/v1.7-gentle which were built on v1.1.

## Test
One-off parameterized import (no files edited):
```python
import replay_check as rc
# Test 4 variants: v1.0 baseline + 3 scale levels
rc.make_trader(frames, "v1.0", scale_into_winners=True, scale_in_max_multiple=1.5)  # gentle
rc.make_trader(frames, "v1.0", scale_into_winners=True, scale_in_max_multiple=2.0)  # mod
rc.make_trader(frames, "v1.0", scale_into_winners=True, scale_in_max_multiple=3.0)  # aggro
```
Live universe (8 tickers: BFST, BKSY, BOX, F, FHB, IP, RCAT, VTEX), 200d lookback, --split-window.

## Results
| Variant | Full Sharpe | 1st Half | 2nd Half | Robust? | Return | Trades | WR |
|---------|------------|----------|----------|---------|--------|--------|-----|
| v1.0 (baseline) | 1.379 | 2.302 | 1.024 | ✅ | +3.6% | 42 | 50% |
| v1.0+scale-gentle | 2.542 | 1.847 | 2.490 | ✅ | +17.1% | 36 | 44% |
| v1.0+scale-mod | 2.540 | 2.160 | 2.816 | ✅ | +17.4% | 37 | 43% |
| **v1.0+scale-aggro** | **3.078** | **2.701** | **2.869** | ✅ | **+30.5%** | 38 | 45% |

**ALL four variants robust in both halves.** Compare to previous test where v1.7/v1.7-gentle (v1.1 core + scale) FAILED robustness.

## Threshold sweep (v1.0 baseline, 25 combos)
24/25 combos robust. Key findings:
- Wider stops (≤-12%): mean Sharpe **1.307**, 9/10 robust
- Narrower stops (≥-8%): mean Sharpe **0.940**, 10/10 robust
- Best combo: -10% stop / 8% target (Sharpe 1.912)
- Current -10%/12% is rank 8, Sharpe 1.379

Wider stops systematically outperform narrower ones — indirect support for the trailing stop hypothesis (premature exits hurt).

## Verdict
**Strong positive: v1.0+scale is robust and high-performing.** The v1.7/v1.7-gentle failure was the v1.1 CORE (MACDh-flip + CHOPPY gate), not the scale-into-winners logic. Scale-into-winners works — it just needs a clean foundation.

### Does this clear the promotion bar?
Technically yes: v1.0+scale-aggro clears both halves (2.701/2.869). But:
1. Tested on only 8 tickers (live universe). Broad-universe test needed before committing.
2. Harness doesn't model the near-zero oscillation guard that makes live MACDh exits different from mechanical flips.
3. Harness doesn't model trailing stops at all — can't prove "drop trailing stops" from these results.
4. The live strategy (v1.6/v1.8) already has scale-into-winners built on v1.1 core. Proving v1.0 core is better means proving the live strategy should shed MACDh-flip + CHOPPY gate — a bigger change than just enabling scale.

### Direction for next session
- Trailing stop (4W/8L) remains the most glaring performance drag. Monitor closely.
- If the near-zero guard keeps preventing false MACDh exits, the live rule may be fine. But the mechanical backup (harness-proven) says: simpler is more robust.
- Consider running v1.0+scale on 250-ticker broad universe with --split-window before the next nightly Evolve.

**Status**: Logged as strong evidence. Does not clear promotion bar (8-ticker test, harness limitations). No strategy.md/params.json changes.
